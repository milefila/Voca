Issue 08

Four Claude interfaces. Most studios are using one.

Most designers work in Claude the same way they work in email. They open the chat box, type a question, read the answer, and close it. That pattern is costing real hours.

Claude is not a single interface. It is four. Each one is built for a different kind of work. Knowing which one to open changes what the tool can actually do for your studio.

Here is how they map to a working design practice.

  The Tools  
1

Chat + Projects — The project brain

Chat is where most designers live. But Chat alone is a short-term memory. Projects changes that. Load a Project with everything that defines a client: the brief, the scope, the budget constraints, the communication style. Claude carries that context into every conversation. Contractor coordination, spec drafts, sourcing decisions, follow-up emails — all of it informed by what the project already contains. You stop re-explaining. The work gets faster.

Use for: client briefs, contractor meetings, image analysis, sourcing, specification writing
2

Cowork — The business engine

Where Chat responds, Cowork executes. This is agentic Claude. You give it a goal, not a question. It reads your files, builds the deliverable, and hands it back. For marketing and content, it handles the full sequence without prompting each step. For business documentation, it produces finished drafts rather than starting points. The distinction that matters: Chat is a back-and-forth. Cowork is a handoff.

Use for: social content, email sequences, proposals, marketing materials
3

Design — The client-facing one

A visual workspace built for output at claude.ai/design. Describe what you need — a pitch deck, a client presentation, a project one-pager — and Claude builds the structure. Not a blank slide. A first draft with logic and layout already in place. The formatting work that used to take hours drops out of the process. For high-stakes presentations, you are editing and adding your photography. You are not starting from scratch.

Use for: pitch decks, client presentations, one-pagers, project proposals
4

Code — The unexpected one

Most designers rule this one out before opening it. That is understandable. It is also worth reconsidering. Claude Code runs longer tasks with access to real files on your computer. The practical application for a non-technical designer is not learning to code. It is building tools that do not exist yet. Custom apps. Client-facing budget trackers. Workflow automation. If there is a tool you have wanted for your practice and never found, this is how you build it. The barrier is not technical knowledge. It is willingness to experiment.

Use for: custom client tools, apps, automation, building what does not yet exist
 

You do not need more software. You need to use what you are already paying for.
